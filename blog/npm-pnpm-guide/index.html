npm/pnpm 包管理实践指南

August 1, 2024 · 4 min read
Mason
Full Stack Developer

包管理器是前端开发的基础工具。本文对比 npm 和 pnpm，分享最佳实践。

📦 包管理器对比​

特性npmpnpm
安装速度慢快 2-3 倍
磁盘占用大（重复安装）小（硬链接）
node_modules 结构扁平化符号链接
幽灵依赖存在避免
Monorepo 支持workspaces内置 workspace

🚀 pnpm 快速上手​

安装​

# 使用 npm 安装
npm install -g pnpm

# 使用 Homebrew
brew install pnpm

# 使用 corepack (Node.js 16.13+)
corepack enable
corepack prepare pnpm@latest --activate

常用命令​

# 安装依赖
pnpm install
pnpm i

# 添加依赖
pnpm add lodash
pnpm add -D typescript    # devDependencies
pnpm add -g serve         # 全局安装

# 移除依赖
pnpm remove lodash
pnpm rm lodash

# 更新依赖
pnpm update
pnpm up lodash
pnpm up --latest          # 更新到最新版本

# 运行脚本
pnpm run dev
pnpm dev                  # 简写

# 执行命令
pnpm exec tsc
pnpm dlx create-react-app my-app  # 类似 npx

📋 package.json 详解​

基本结构​

{
  "name": "my-project",
  "version": "1.0.0",
  "description": "项目描述",
  "main": "dist/index.js",
  "module": "dist/index.mjs",
  "types": "dist/index.d.ts",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "vitest"
  },
  "dependencies": {
    "react": "^18.2.0"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}

版本号规则​

主版本.次版本.补丁版本
  ^     ~     无前缀

^18.2.0  → >=18.2.0 <19.0.0  (允许次版本和补丁更新)
~18.2.0  → >=18.2.0 <18.3.0  (只允许补丁更新)
18.2.0   → 精确版本
*        → 任意版本
>=18.0.0 → 大于等于

依赖类型​

{
  "dependencies": {
    // 生产依赖，打包会包含
  },
  "devDependencies": {
    // 开发依赖，打包不包含
  },
  "peerDependencies": {
    // 对等依赖，宿主项目需要安装
    "react": "^18.0.0"
  },
  "optionalDependencies": {
    // 可选依赖，安装失败不会报错
  }
}

🔒 锁文件​

package-lock.json (npm)​

{
  "name": "my-project",
  "lockfileVersion": 3,
  "packages": {
    "node_modules/lodash": {
      "version": "4.17.21",
      "resolved": "https://registry.npmjs.org/lodash/-/lodash-4.17.21.tgz",
      "integrity": "sha512-..."
    }
  }
}

pnpm-lock.yaml​

lockfileVersion: '6.0'
dependencies:
  lodash:
    specifier: ^4.17.21
    version: 4.17.21
packages:
  /lodash@4.17.21:
    resolution: {integrity: sha512-...}

最佳实践​

✅ 提交锁文件到 Git
✅ 不要手动修改锁文件
✅ 团队使用相同包管理器
✅ CI 使用 npm ci / pnpm install --frozen-lockfile

⚙️ 配置文件​

.npmrc​

# 镜像源
registry=https://registry.npmmirror.com

# 私有仓库
@mycompany:registry=https://npm.mycompany.com

# 认证
//npm.mycompany.com/:_authToken=${NPM_TOKEN}

# 其他配置
save-exact=true
engine-strict=true

.nvmrc​

18.17.0

engines 字段​

{
  "engines": {
    "node": ">=18.0.0",
    "pnpm": ">=8.0.0"
  }
}

🛠️ 实用技巧​

1. 查看依赖信息​

# 查看包信息
npm info lodash
pnpm info lodash

# 查看已安装版本
npm ls lodash
pnpm ls lodash

# 查看过期依赖
npm outdated
pnpm outdated

# 查看依赖树
npm ls --all
pnpm ls --depth 3

2. 清理缓存​

# npm
npm cache clean --force

# pnpm
pnpm store prune
pnpm store path  # 查看存储路径

3. 安全审计​

# 安全检查
npm audit
pnpm audit

# 自动修复
npm audit fix

4. 发布包​

# 登录
npm login
pnpm login

# 发布
npm publish
pnpm publish

# 发布测试版
npm publish --tag beta

# 设置版本
npm version patch  # 1.0.0 -> 1.0.1
npm version minor  # 1.0.0 -> 1.1.0
npm version major  # 1.0.0 -> 2.0.0

📂 Workspaces​

pnpm-workspace.yaml​

packages:
  - 'packages/*'
  - 'apps/*'

目录结构​

my-monorepo/
├── package.json
├── pnpm-workspace.yaml
├── packages/
│   ├── shared/
│   │   └── package.json
│   └── utils/
│       └── package.json
└── apps/
    ├── web/
    │   └── package.json
    └── api/
        └── package.json

Workspace 命令​

# 安装所有包的依赖
pnpm install

# 在特定包中运行命令
pnpm --filter @myorg/web dev
pnpm -F @myorg/web dev

# 在所有包中运行命令
pnpm -r build
pnpm --recursive build

# 添加包之间的依赖
pnpm -F @myorg/web add @myorg/shared

# 添加外部依赖到特定包
pnpm -F @myorg/web add lodash

# 添加到根项目
pnpm add -w typescript

🔧 脚本技巧​

并行/串行执行​

{
  "scripts": {
    "build:all": "pnpm -r build",
    "dev": "pnpm -r --parallel dev",
    "test": "pnpm -r --sequential test"
  }
}

前置/后置脚本​

{
  "scripts": {
    "prebuild": "rm -rf dist",
    "build": "tsc",
    "postbuild": "echo 'Build complete!'"
  }
}

跨平台脚本​

# 安装 cross-env
pnpm add -D cross-env

# 使用
"scripts": {
  "build": "cross-env NODE_ENV=production webpack"
}

❓ 常见问题​

幽灵依赖​

问题：项目中使用了未声明的依赖（通过其他包间接安装）

npm：扁平化安装，可能可以使用未声明的包
pnpm：严格模式，必须显式声明

解决：使用 pnpm 或明确声明所有使用的依赖

依赖冲突​

# 查看为什么安装了某个版本
pnpm why lodash

# 强制使用特定版本
# package.json
{
  "pnpm": {
    "overrides": {
      "lodash": "4.17.21"
    }
  }
}

安装失败​

# 清理重试
rm -rf node_modules
rm pnpm-lock.yaml
pnpm install

# 忽略脚本
pnpm install --ignore-scripts

📚 推荐配置​

{
  "scripts": {
    "preinstall": "npx only-allow pnpm"
  },
  "packageManager": "pnpm@8.10.0",
  "engines": {
    "node": ">=18.0.0",
    "pnpm": ">=8.0.0"
  }
}

选择 pnpm 可以获得更好的性能和更严格的依赖管理。对于新项目，推荐使用 pnpm。
